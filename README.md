# Help_me_clean · «Наведи и убери»

Домашнее приложение, которое учит ребёнка убираться: ведёт по комнатам его
дома, показывает камерой, что именно надо убрать, и превращает это в короткие
выигрываемые раунды. Для детей и «kidults».

Приложение из семейства **Twin**: PWA без сборки (vanilla JS ES-модули), хостинг
на GitHub Pages, **отдельный** Firebase-проект (Auth + Firestore + Storage),
LLM с vision через существующий Cloudflare Worker.

- **Живой сайт:** https://natalyatsarapaeva-tech.github.io/Help_me_clean/
- **Обоснование архитектуры:** [`docs/AUTH-i-pereispolzovanie.md`](docs/AUTH-i-pereispolzovanie.md)

## Двухуровневая авторизация «пользователь → семья»

Как в Twin Things, по коду (перенос many-to-many модели):

- **Уровень 1 — пользователь.** Firebase Auth. Родитель — email/пароль или Google;
  ребёнок — служебный аккаунт за аватаром + 4-значным PIN (`js/child-auth.js`:
  PIN расшифровывает пароль на устройстве через WebCrypto).
- **Уровень 2 — семья.** `families/{fid}` — контейнер (дом, профили, награды,
  эталоны). Членство: `families/{fid}/members/{uid}` — источник прав
  `{role: parent|child}`. Ребёнок заперт в свой профиль (`profileId == uid`) —
  правилом базы, а не только интерфейса.
- **Код семьи** — для добавления **взрослых** устройств (второй родитель, второй
  телефон). Дети код не вводят. Join через Worker — пока не реализован (не нужен для MVP).

## Образ («кто ты сегодня») — выбор ребёнка, не настройка

Тема (🟡 Миньон / 🔵 Джедай) **не задаётся родителем и не хранится как свойство
профиля**. Ребёнок выбирает её сам на входе и может менять когда угодно —
это про настроение, а не про возраст (§24 ТЗ: «ребёнок выбирает не уровень
сложности, а кто он»).

Что при этом происходит с накопленным:

| Что | Принадлежит | Почему |
|---|---|---|
| Искорки (валюта), счётчик уборок, реальные награды | **ребёнку** | Смена образа ничего не отнимает — потеря прогресса убивает мотивацию (§336) |
| Коллекция карточек | **образу** (`cardsByTheme`) | У миньонов свои существа, у джедаев свои — смена показывает другую витрину |
| `lastTheme` в профиле | подсказка | Только последний выбор (для родителя и предзаполнения), не настройка |

Механика под обоими образами одна и та же — различаются палитра, тексты,
размер шага и озвучка (`THEMES` в `js/family-core.js`).

## Модель данных (Firestore)

```
users/{uid}                              — профиль {displayName, email, createdAt}
users/{uid}/families/{fid}               — индекс «мои семьи» {role, name, joinedAt}
families/{fid}                           — {name, ownerUid, joinCode, createdAt}
families/{fid}/members/{uid}             — ИСТОЧНИК ПРАВ {role: 'parent'|'child'}
families/{fid}/profiles/{pid}            — профиль ребёнка (pid == uid): name, avatar,
                                           lastTheme (последний выбор, НЕ настройка), routeOrder
families/{fid}/profiles/{pid}/progress/{sessionId}
families/{fid}/profiles/{pid}/rewards/current
    { currency, cleanupsTotal, realRewards,  ← общие: принадлежат РЕБЁНКУ
      cardsByTheme: { minion: [...], jedi: [...] } }  ← коллекции РАЗНЫЕ у тем
families/{fid}/home/map                  — карта дома + маршрут
families/{fid}/settings/app              — плейлисты, бюджет
families/{fid}/reference/{surfaceId}     — эталонные фото
families/{fid}/cards/{cardId}            — коллекция
```

## Грабли, на которые уже наступили (чтобы не повторять)

1. **Правила Firestore и Storage — РАЗНЫЕ редакторы.** Firestore-правила,
   вставленные в редактор Storage, «публикуются», но Firestore продолжает
   отклонять всё дефолтным deny → `permission-denied` на первом же чтении.
   Различать по URL (`/firestore/` vs `/storage/`) и по первой строке
   (`service cloud.firestore` vs `service firebase.storage`).
2. **Storage-правила читают Firestore** (`firestore.exists(...)`) → при публикации
   консоль просит выдать IAM-роль служебному аккаунту Storage. Надо согласиться.
3. **PWA-кэш маскирует правки.** Если кажется, что код на Pages «не обновляется» —
   проверять в инкогнито; при отладке временно отключать service worker в `pwa.js`.
4. **Диагностика в `index.html`:** плашка `#err-box` показывает `code`, `message`,
   шаг записи, реальный `projectId` и `uid` прямо на странице. Полезна при
   настройке; когда приложение стабилизируется — можно убрать.
